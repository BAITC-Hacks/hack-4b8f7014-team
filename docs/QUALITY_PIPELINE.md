# Улучшение качества протоколов

## Реализованные механизмы

`MINUTES_GROUNDED_EXTRACTION=true` включает отдельный адаптер `GroundedExtractor`:

- Блоки учитывают паузы и смену говорящего, ограничены по размеру, имеют перекрытие четырёх реплик. Короткие записи остаются целиком, чтобы не потерять контекст назначения.
- Первый проход помечает кандидатов на поручения короткой цитатой и номером предложения. Лексические маркеры дополняют поиск. Второй разбирает группы до трёх кандидатов с шестью соседними предложениями с каждой стороны: новые поручения против прошлых событий, ответственных и сроки. Факты и итоговое саммари формируются отдельными проходами. Для помещающегося в контекст материала отдельная завершающая сверка объединяет повторы и уточняет окончательные сроки; на длинном материале этот общий проход пропускается.
- Для действия, ответственного и срока используются отдельные дословные цитаты. Несуществующая цитата не подтверждает поле. Различия пробелов и регистра нормализуются с восстановлением буквального текста источника. Ошибочный номер фрагмента можно исправить только по единственному буквальному совпадению.
- Ответственный и срок без подтверждения очищаются с предупреждением. Исторические события и обсуждения исключаются по классификации модели. Ошибка классификации всё ещё возможна.
- В следующий блок передаются последние 30 задач и имена из уже извлечённых задач. Это контекст, а не подтверждение личности.
- Саммари формируется отдельным проходом по проверенным цитатам фактов и черновым задачам. Числа, потерянные при сокращении, возвращаются из фактов. Это сохраняет извлечённые числовые факты, но не гарантирует, что первый проход нашёл все числа записи.
- Все задачи остаются черновиками. `verified` подтверждает наличие цитаты, а не семантическую правильность исполнителя или срока.

Не используется жёсткий предварительный фильтр только по словам «поручаю» или «нужно»: он мог бы потерять неявно сформулированное поручение. Поиск кандидатов моделью покрывает весь блок. Длинные реплики предварительно делятся на предложения без изменения хранимого транскрипта.

`MINUTES_EXCLUSIVE_DIARIZATION=true` использует exclusive output Community-1. Обычные и exclusive интервалы сохраняются локально в `data/diarization`. Короткое слово на паузе получает соседний голос только при согласии известных меток с двух сторон и отсутствии пересечения с другим голосом. На смене голосов неопределённость сохраняется. Число неизвестных фрагментов не является DER.

`source_speaker_id` явно обозначает источник высказывания; старое `speaker_id` сохранено для совместимости. `responsible` хранится отдельно. Имена голосам по-прежнему назначает пользователь. Список имён перед обработкой используется только как подсказка STT и может внести смещение, поэтому результаты с подсказкой оцениваются отдельно.

## Модели

Кандидат для сравнения — [Qwen3 8B Q4_K_M](https://ollama.com/library/qwen3:8b). Новизна модели не доказывает улучшение на наших записях. Локальная загрузка:

```powershell
./data/runtime/ollama/ollama.exe pull qwen3:8b
```

Для сравнения на сохранённом транскрипте:

```powershell
python -m scripts.evaluate_extraction --model qwen3:8b --transcript data/transcripts/MEETING-diarized.json --output data/eval/comparison.json
```

Эталонный протокол в запрос не передаётся. Результаты, записи и локальные данные не коммитятся.

Проверка предложенных STT-моделей 23 сентября 2026:

- [shyngys879/kazakh-whisper-large-v3-turbo](https://huggingface.co/shyngys879/kazakh-whisper-large-v3-turbo): публичный Transformers checkpoint, Apache-2.0, revision `dafae810c95496f66184605824be5a0a971d3c09`; готового CT2 model.bin не обнаружено.
- [olzhasAl/whisper-large-v3-tulpar](https://huggingface.co/olzhasAl/whisper-large-v3-tulpar): публичный checkpoint, Apache-2.0, revision `a87c8df933ae97ff8bf04f465d43490422473a70`; готового CT2 model.bin не обнаружено.
- `alibiserikbay/kazakh-russian-mixed-stt`: запрос публичного API вернул 401; существование общедоступного подходящего checkpoint не подтверждено. Это не доказательство отсутствия приватной модели.

Специализированные модели пока не подключены. Нужны конвертация, проверка лицензий сопутствующих компонентов и независимое сравнение RU/KZ/mixed. Повторное распознавание спорных отрезков пока выполнялось диагностически; автоматическая замена текста по второй модели не внедрена.

## Приёмочный набор

Цель — 8–12 записей RU, KZ и смешанной речи по 3–15 минут. Сейчас такого размеченного набора нет; результаты нескольких демонстраций не заменяют приёмку.

Для каждой записи до эксперимента фиксируются версия аудио, дословный текст, голоса по времени, задачи, исполнитель, исходная формулировка срока, разрешимость даты и ключевые факты. Сомнительные расхождения Word и аудио сверяются на слух. Настройка на одной записи требует отдельной контрольной записи.

Метрики: полнота задач = TP/(TP+FN), precision = TP/(TP+FP); доля верных исполнителей и сроков на сопоставленных задачах с явным знаменателем; сохранение ключевых числовых фактов; DER только при временной разметке голосов; время на минуту аудио и пиковые RAM/VRAM. Пустой ответственный лучше выдуманного, но учитывается как пропуск, а не как правильный ответ.

Источники реализации: [Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1), [настройки памяти Ollama](https://github.com/ollama/ollama/blob/main/docs/faq.mdx).

## Профиль памяти на Windows

Скрипт запуска включает `OLLAMA_FLASH_ATTENTION=1` и `OLLAMA_KV_CACHE_TYPE=q8_0`.
Это настройка локального сервера, для применения нужен его перезапуск.
На RTX 4060 Laptop Qwen3 8B с контекстом 16384 после изменения разместилась
полностью на GPU: API Ollama показал size = size_vram = 6270348164 байт.
Наблюдавшаяся генерация выросла примерно с 9 до 41 токена/с. Это наблюдение
одного прогона, а не измерение полного времени обработки совещания.
Квантование контекста способно менять ответы, поэтому качество проверяется заново.

## Проверенные ограничения схемы

На начальном прогоне Qwen3 извлекла 10 вместо 9 задач и исправила срок инструктажа,
но всё ещё ошибалась в исполнителях и пропускала цифры. Поэтому замена модели сама
по себе не считается исправлением. Для повторного прогона добавлены:

- запрет назначения адресата фразы «можно добавить?» только на основании этой фразы;
- буквальные числовые предложения с процентами и распространёнными единицами,
  извлекаемые независимо от полноты LLM; числа, записанные словами, этот механизм
  не покрывает полностью;
- сохранение факта цитатой вместо свободного пересказа поля показателя;
- восстановление отдельных ссылок на цитаты ответственного и срока.

Числа и наличие цитат — программно проверяемые свойства. Смысл назначения,
корректность даты и причинно-следственных утверждений по-прежнему требуют сверки.

## Включение после скачивания Qwen3

В `.env` установите:

```dotenv
MINUTES_OLLAMA_MODEL=qwen3:8b
MINUTES_GROUNDED_EXTRACTION=true
MINUTES_EXCLUSIVE_DIARIZATION=true
```

Перезапустите API и worker. Для режима Qwen2.5 старой схемы оставьте
`MINUTES_GROUNDED_EXTRACTION=false` и прежнее имя модели. Сохранённые протоколы
автоматически не переписываются. Обе модели остаются на диске.

На записи №1 локальный повтор диаризации и согласование границ дали 7 неизвестных
фрагментов из 29 вместо исходных 20 из 52. Границы и число фрагментов изменились;
это не процент правильной диаризации и не DER. Метки голосов не являются именами.
