# Обработка записей — второй этап

Этот документ обновляет первоначальный план в ARCHITECTURE.md и ON_PREM.md.
Реализованы локальные адаптеры, очередь, worker, проверка поручений и экспорт.
Веса моделей не включены в Git. Локальный полный прогон на двух синтетических
RU-записях прошёл; подробности в LOCAL_MODELS.md. Качество на реальных совещаниях
и RU/KZ/смешанной речи пока не измерено.

## Запуск

1. Установите `requirements.txt`, FFmpeg и локальный сервер Ollama.
2. Подготовьте веса по `models/README.md`. Worker не скачивает модели автоматически.
3. Скопируйте `.env.example` в `.env`, укажите пути моделей.
4. Для PDF задайте `MINUTES_PDF_FONT`: TTF с RU/KZ, например DejaVu Sans на Linux
   или `C:/Windows/Fonts/arial.ttf` на Windows. Шрифт не скачивается при экспорте.
5. Запустите API и Streamlit по README, затем в третьем терминале:

```bash
python -m app.worker
```

В интерфейсе загрузите файл, выберите язык (`mixed` для смешанной речи), укажите дату
совещания, если она известна, и нажмите «Обработать запись». Кнопка «Обновить состояние»
показывает этап. После завершения доступны транскрипт, саммари, имена говорящих,
проверка ответственных/сроков и экспорт. Имена говорящих не становятся автоматически
ответственными: говорящий может поручать работу другому человеку.

## Что происходит

`FFmpeg → mono 16 kHz WAV → faster-whisper → pyannote → Ollama JSON → SQLite → DOCX/PDF`.
STT использует временные метки слов. Пересечения диаризации сопоставляются со словами;
при неоднозначном говорящем сохраняется unknown. Ollama получает части транскрипта
с идентификаторами. Цитата поручения должна находиться в указанном сегменте. При
несовпадении выполняется один запрос на исправление цитаты. Если исправить не удалось,
поручение сохраняется как `evidence_status=unverified`, без подтверждённой цитаты и
без привязки к говорящему; исходное предложение модели хранится отдельно. Интерфейс
и экспорт явно предупреждают о необходимости проверки. Другие поручения сохраняются.
Это проверка происхождения цитаты, не гарантия правильного
смысла, ответственного или срока: их подтверждает человек.

API возвращает 202 при постановке в очередь, 409 для уже поставленных/готовых записей.
Worker один на папку данных (блокировка ОС). При рестарте он восстанавливает running
задания; результат и поручения записываются одной транзакцией. Неудачное задание можно
повторить. Ручные поручения сохраняются. Ошибки не раскрывают текст записи в интерфейсе.

## Ограничения и дальнейшая работа

Транскрипт сохраняется атомарно после STT и после диаризации в `data/transcripts/`.
При ошибке следующих этапов он доступен в интерфейсе и через
`GET /meetings/{id}/transcript`. Повтор обработки пока выполняет все этапы заново.

- Автотесты используют подмены; дополнительно выполнен реальный полный прогон
  с локальными моделями на двух синтетических записях (см. LOCAL_MODELS.md).
- Модели загружаются на каждое задание. CPU по умолчанию; CUDA требует настройки.
- Запись ограничена 2 часами, декодирование — 10 минутами, запрос Ollama — 5 минутами.
  Для зависшего STT/диаризации перезапустите worker: отдельного watchdog пока нет.
- Саммари частей объединяются; возможны повторы и потеря контекста между частями.
- Относительные сроки требуют даты совещания; проверка человеком обязательна.
- PDF требует локального Unicode-шрифта. DOCX использует Arial, который должен быть
  установлен у получателя. Экспорт всегда помечен как черновик ИИ.
- Нужны настоящие тесты RU/KZ/смешанной речи, улучшение транскрипта и длинных записей,
  напоминания, локальная рассылка и интеграция с СЭД. Авторизации пока нет, только loopback.

Источники API: [faster-whisper](https://github.com/SYSTRAN/faster-whisper),
[pyannote Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1),
[Ollama JSON Schema](https://docs.ollama.com/capabilities/structured-outputs).
